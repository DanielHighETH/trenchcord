## Trenchcord v2.0.0 — 2026-08-21

### Changed
- **Links to Discord and Telegram now open the apps by default** — clicking through to a message's original (the source badge, a DM's conversation badge, a Contracts-feed entry) used to open discord.com or t.me in the browser unless you had switched the two **Open in Discord App** / **Open in Telegram App** settings on; both now default to on, so the click lands in the app where you can actually reply. The switches under Settings → General still turn the browser behavior back on, and anyone who already made a choice keeps it (all platforms)
- **Reply lines now look like Discord's** — the line above a reply used to be the replied-to name and their text, nothing else; it now carries their avatar, their role colour and an APP tag when they're an app, with the name written **@name** exactly as Discord draws it. Replies to a message that is only an image, a sticker or a bot embed — a Bark alert, a Rick scan — used to leave that line blank, because there was no text to quote; they now read *Click to see attachment* next to the attachment glyph, so what's being answered is clear without scrolling to it. Telegram replies gained the avatar and the tag too (all platforms)
- **Buy buttons now cover every token a message points at, not just the written-out one** — a post that names its tokens only as links (Bark's `/pf callouts` lists, leaderboards, "top calls today" round-ups) used to get no buy row at all, because the contract lived inside the link and nowhere in the text; each of those tokens now gets its own row, labelled with the name it was linked under so the rows are told apart without reading addresses. The row still starts at three and the "+N more contracts in this message" line is now a button that expands the rest (up to twelve). Links only get to name a token when the message writes none out, so a scanner bot that posts one contract and links a few others beside it — Rick's row of compared tokens — still gets exactly one buy row, for the token it actually scanned. Wallet, profile and transaction links are skipped — a caller's pump.fun profile never grows a buy button — and the on-chain mint check removes anything that isn't a token (desktop app + iOS)
- **Walkthrough video on the landing page** — the 90-second app walkthrough closes the "Everything You Need" grid as a wide "See It All in Action" card (web-optimized to 3.5 MB, with a poster frame so nothing heavy loads until you press play) (landing page)
- **Landing page Security section now discloses the cloud** — with official builds verifying subscriptions against `api.trenchcord.app`, the section no longer claims "no cloud at all": it lists exactly what the app sends (a device token for the subscription check, a device name when pairing, and — only if you use Alerts — the watchlists you define) and what is never sent, linking the README's full request-by-request list. The navbar also puts Download first and gained a Discord link next to X and GitHub, and Pricing's included-list now mentions the iPhone app (in beta via TestFlight) with devices counting into the same subscription (landing page)
- **Landing page hero preview rebuilt** — the app mockup on trenchcord.app now mirrors the current app (feeds sidebar with Contracts/Mentions/Keywords/Snipes/Alerts, rooms, Telegram DMs, server/channel source badges, keyword & CONTRACT badges) and is interactive: switch rooms, watch live messages stream into #main with unread counters, click a username to highlight them everywhere, click a contract. The hero copy now mentions Telegram aggregation, and the "Everything You Need" grid gained the newer features: auto-sniping, in-chat buy buttons, cloud Alerts, split-screen, pop-out windows, the built-in feeds, hotkeys, message search, and full rendering of threads/polls/stickers/bot panels (landing page)
- **License: AGPL-3.0 → Trenchcord Source-Available License** — the source stays fully public so anyone can audit exactly what Trenchcord does (and what leaves their machine), and building it yourself for evaluation and verification is explicitly allowed. Day-to-day use now requires an active subscription, whether you run an official build or your own, and redistribution is not permitted. Releases published before this change remain under the AGPL-3.0
- **Notifications no longer bury the phone screen** — alert toasts (highlighted users, keywords, contracts, cloud alerts) and the buy-result toast used roomy, semi-transparent desktop panels that stacked up to five deep and covered most of a phone display; on phones they are now slim, fully opaque banners (buy results as a solid green/red pill sitting above the room bar), and at most two alert toasts stack at once. Desktop keeps the roomy panels but loses the transparency: their background was a 10% colour wash and nothing else, so the room header's buttons and the message behind them read straight through the text — the alert's colour is now a tint on a solid panel (all platforms)
- **Linking a device now starts with one question, on desktop and phone alike** — the link screen first asks **"Do you already have a Trenchcord account?"**; either answer shows the pairing code immediately (signup happens right on the dashboard page that approves the code, and the code survives signing in or up), the answer just tailors the instructions — "No" turns the big button into **Create your account**. The code screen itself got a cleaner look, especially on the phone: the dashboard link is now a proper button instead of a wrapping text link, and a **Back** button returns to the question. After approving on the iPhone, the dashboard shows an **Open Trenchcord** button that jumps straight back into the app, and the renew/manage-subscription links show on the phone too. Payment itself still always happens on the web dashboard, never in the app (desktop + iOS)
- **Signing in with Telegram no longer needs the telegram.org widget** — the account dashboard now signs you in with a bot code: open the Trenchcord bot, send `/start`, and type the 6-character code it replies with — straight from the Telegram app. Linking a Discord account works the same bot-code way under Connected accounts (message the bot from the Discord app, no discord.com web login), Discord sign-in itself stays browser OAuth, and the sign-in screens carry far less text (account dashboard)
- **Sidebar swipe gestures now need a deliberate pull (phones)** — opening the menu with a swipe from the left edge, and closing it with a swipe left, used to trigger on the slightest graze; both now require pulling about a quarter of the screen in a clearly horizontal motion, so scrolling the chat or the room list no longer flings the menu around (iOS + mobile web)
- **Auto-update is now opt-in (Windows)** — the Windows app no longer checks for or downloads updates on its own. A new **Automatic Updates** toggle under Settings → General controls it, **off by default**: with it off, the app never contacts GitHub for updates and nothing is ever downloaded or installed without you turning it on. Update manually from the [releases page](https://github.com/DanielHighETH/trenchcord/releases/latest), or flip the toggle on to get the old behavior (check at launch, download, and ask before installing)
- **Backup & Restore is now its own Settings section** — exporting and importing your settings used to hide at the very bottom of Help & Features; it now has its own **Backup & Restore** entry in the settings sidebar, right below Guilds (all platforms)
- **The landing page Setup Guide now opens on Installation** — the Installation and Requirements tabs swapped places: most visitors grab the desktop app, so the guide leads with that instead of the from-source prerequisites (landing page)
- **Message timestamps drop the "Today at"** — nearly every message in view is from today, so the prefix was on every single line for no information; today's messages now show just the time, while yesterday's and older ones keep "Yesterday at" and their date (all platforms)

### Added
- **iOS app — Trenchcord on your iPhone (beta via TestFlight)** — the native iPhone app ships with Trenchcord 2.0: rooms, panes, all the feeds, Telegram, and full trading and sniping on the phone — the buy buttons, Trading and Sniping settings, and the Snipes feed all work on iOS. Devices count into the same subscription. Two phone-specific notes: snipes only fire while the app is open and in the foreground (iOS suspends apps otherwise), and the Slotshark API token is never carried over by a settings import — enter it on the phone under Settings → Trading. Backgrounding is handled gracefully: after any stay in the background — even a long one — the app reconnects Discord, Telegram, and its own backend by itself the moment you return (iOS)
- **Trenchcord Cloud accounts & subscriptions** — official desktop builds can now link to a Trenchcord account with a one-time device code and unlock cloud-gated features (like Alerts) via a subscription paid in SOL (1 / 3 / 12-month plans). Entitlement is verified against `api.trenchcord.app` on startup and periodically; everything sent is documented in the README's transparency section. Linking is friction-free: the gate first asks whether you already have an account (with a shortcut to create one on the dashboard), the pairing code has a copy button, and the dashboard link carries the code with it — it survives signing in or signing up, so it's pre-filled and one click approves the device. The dashboard's Linked Devices section also gained a "Link a device" button (shown while you're under the device limit)
- **A room can follow a whole Discord category** — rooms were built one channel at a time, so a server that spreads its calls over a dozen channels cost a dozen clicks, and a channel opened next week never arrived on its own. Category names in the room's Channels tab now carry an **Add category** button: the room takes every channel under it and keeps following it, so a channel created in that category joins the room by itself and one deleted or moved out leaves — no reopening the room, and it works while the room is live. Channels can still be switched off one by one inside a followed category (they read **OFF** and stay off however the category changes), and a channel you also pick on its own keeps its own settings, such as embeds off (all platforms)
- **App messages now carry Discord's APP tag** — anything posted by a bot or a webhook now shows the blue **APP** badge next to the name, the way Discord marks it: in both message layouts, on the reply line above a message, and next to the poster in the Contracts feed. A scanner's call is never read as a person's again, and Telegram bots are tagged the same way (all platforms)
- **Bot answers now say which command produced them** — when a bot message is the reply to a slash command, Trenchcord shows Discord's own line above it: who ran it and what they ran (**marc used /pf callouts**), with a click on the command copying it so the same call can be fired again in one paste. Callout and trading bots answer commands all day, and their embeds used to arrive with no hint of what had been asked — you'd see "Page 1 of 6" with no idea whose question it answered (all platforms)
- **Account dashboard, in-app** — Settings → Account & Subscription now mirrors dashboard.trenchcord.app once your device is linked: **extend your subscription without leaving the app** (pick a plan, pay in SOL via a Solana Pay QR code or a copyable one-time deposit address, with live payment detection and automatic crediting — open payments can be resumed or cancelled), and see your **linked devices**, **connected accounts**, and **payment history** with Solscan links. Connected accounts are read-only in-app and device revocation stays on the web dashboard — linking identities and revoking devices deliberately require a full dashboard login, not just a device token. The new requests are documented in the README's "What Leaves Your PC" section (desktop app)
- **Alerts** — alerts that fire even while your PC is off, because they run on Trenchcord Cloud (an active subscription is required — the evaluation happens server-side). Managed on a new **Alerts** page with its own sidebar feed and hotkey (desktop app):
  - **Price alerts** — CEX pairs (Hyperliquid, Binance fallback), DEX tokens by market cap on Solana / Ethereum / BSC / Base / Robinhood / Monad / Tron, stocks, and the five metals, with goes over / goes under / ±% conditions. Pasting a DEX address (or typing a symbol/ticker) shows a live preview of the token's name, price, and market cap before you save, and shorthand values like `5k` / `1.5m` display their full amount (`= $5 000`) as you type
  - **X account alerts** — new post, keyword match, reply to someone, interaction with a specific post, or new follow, with an optional post-type filter (original posts / replies / quotes / retweets)
  - **Telegram channel alerts** — any post or keyword match in a public channel, watched by Trenchcord's own watcher accounts — your Telegram login is never used
  - **Delivery to your phone** — Pushover, Telegram DM, and/or Discord DM, pushed by Trenchcord Cloud the moment an alert fires — each channel has its own on/off toggle, so any combination works. The bots link with a one-time `/start` code (no account connection), at least one channel is required before creating alerts, and the Pushover user key is shared both ways with Settings → Pushover so you never enter it twice
  - **Sound settings** — define what "Normal" and "Critical" mean for Pushover: any of the five priorities (each explained in plain language) and any of the 23 sounds, with ▶ previews. Emergency priority gets retry/expire tuning and a guide (with screenshot) to the recommended Pushover app settings — including the Critical Alerts toggle that breaks through silent/DND. Any alert can also override the sound and priority just for itself. Pushover titles are prefixed `Trenchcord ·` so alerts are recognizable at a glance
  - **Creating & managing** — a step-by-step picker (what to watch → which kind → a short form with pill buttons instead of dropdowns), comma-separated keywords preview as badges as you type, and a one-click DEX alert from the Contract feed's bell button. Alerts live in a card grid that adapts to the pane's width and works in pop-out windows; every card can be edited (including the condition — changing it re-arms the alert, and percent edits re-capture their baseline), paused, deleted, or **reactivated in one click** after it fires — the card flips to FIRED live when the alert triggers
  - **In-app alerts too** — fired alerts land in the Alerts feed (clearable one-by-one or all at once), plus toasts, a dedicated notification sound, and desktop notifications while the app is open
  - Every request involved is documented in the README's "What Leaves Your PC" section
- **Auto-sniping** — Trenchcord can now buy a token the instant it's called, with no click at all. Create snipe configs right on the **Snipes** feed page: pick a room, follow **specific callers** (the default) or snipe **everything** posted there, and set the SOL amount and which of your Slotshark wallets fire. Each config can override slippage, tip, and priority fee, set min/max market cap bounds (enforced server-side by Slotshark), and attach automatic limit sells. Safety rails are built in: failed buys never retry themselves into a loop, and the snipe ledger survives restarts. Snipes trigger even when a caller bot attaches the contract via an edit moments after posting — the common Rick-style pattern (desktop app)
- **Re-snipe policies** — choose per snipe config what happens when the same token is called again: **never re-snipe** (one buy per token, ever — the default), **after a cooldown** in seconds, or **up to X times** per token and then stop. Whatever the mode, the same message can never fire twice, so a bot editing its own call won't double-buy (desktop app)
- **Keyword-triggered snipes** — map keywords to contract addresses inside a snipe config: when one of your followed callers writes e.g. `ANSEM`, Trenchcord instantly buys the contract you mapped to that word — no address needs to appear in the message at all. Keywords match whole words in any casing, including inside embeds and bot panels, and re-snipe rules apply per token as usual (desktop app)
- **Snipes page manages your configs** — snipe configs live on the Snipes feed itself, in an Alerts-style card grid at the top of the page: a create card plus one card per config (active/paused/no-wallet badge, room, callers, SOL amount) that opens the full editor in a modal — edit, pause, or delete without leaving the feed. The panel shares the feed's background so the page reads as one surface. The global **Enable Sniping** switch moved to Settings > Trading, right under Enable Trading, and the Sniping settings section is gone (desktop app)
- **Skip if already bought** — a per-config snipe toggle that tells Slotshark to skip the buy when the wallet already holds the token (checked server-side at execution time, per wallet), so a token you're already in — from any config or a manual buy — doesn't get a second position stacked on top (desktop app)
- **Snipes feed onboarding** — an empty Snipes feed shows a step-by-step setup checklist (create a Slotshark account, get the API token, connect it under Settings > Trading, enable sniping and add a config on the page itself) instead of a blank page, with each finished step ticked off (desktop app)
- **Scripted demo tour** — the sample-data demo can now play a self-running walk-through for promo videos: open the demo build with `?tour` (or `?tour=loop` to repeat forever) and a guided cursor tours rooms, live messages with a Rick-style scan, a one-click buy, the sniper, split view with resize and pop-out, Telegram, Alerts, and compact mode, with caption cards narrating each scene (demo build only — never active in the real app). The demo's sample data was also rebuilt to look like real trenching: three realistic servers plus Telegram channels merged into rooms, natural chat with replies and reactions, scanner-bot output, and a fully set-up trading/sniping config with simulated buys
- **Image viewer with zoom** — clicking an image now opens a full-screen viewer you can actually zoom: click the image or spin the mouse wheel on the computer, pinch and double-tap on the phone, drag to pan, with a save button. Images from Discord's CDN also get an **open in browser** button that shows the full-size original in a new window
- **Clickable notification toasts** — clicking a highlighted-user, keyword, or contract toast now jumps to the message: either to its room inside Trenchcord (default) or to the original in Discord / Telegram, chosen under Settings > General > Notification Click
- **Clear a DM conversation** — hovering a Discord or Telegram DM in the sidebar now shows an eraser button that empties it and drops it out of the list; the person reappears the moment they message you again. The same clear sits in the DM's own header (in the overflow menu on phones) (all platforms)
- **Clear messages in Mentions and Keywords** — the two feeds pile up over a session with no way to work through them. Each entry now has a small ✕ (on hover on desktop, always visible on phones) that clears just that one, and the header has an eraser button that clears the whole feed after a confirmation. New matches keep arriving as usual (all platforms)
- **Help & Features refresh** — the in-app guide (Settings > Help) now covers everything that shipped recently: split screen and pane locking, pop-out windows, all five built-in feeds, Telegram channels in rooms, trading, auto-sniping, cloud Alerts, hotkeys (room, feed, bring-to-front), and the threads/polls/stickers/GIF rendering work
- **Snipes feed** — a new sidebar feed collecting every message that triggered a snipe, with a colored outcome badge on each: green `SNIPED 0.5 SOL (2/2)` with the config name, orange `SNIPE SKIPPED`, or red `SNIPE FAILED`, with the reason in the tooltip. Works like Mentions: open it in a pane, split it, pop it out (desktop app)
- **Keywords feed** — every keyword-matched message across your rooms now also collects into a dedicated Keywords feed with the matched keyword badge, so you can review past matches instead of relying on catching the toast
- **Feed hotkeys** — assign single-key hotkeys to the Contract feed, Mentions, Keywords, and Snipes under Settings > General, exactly like room hotkeys. Room hotkeys win if a key is used twice
- **Contract feed shows the message** — each contract entry now shows who posted it (avatar and name), where, and the message text itself, in both the table and card views, so you can judge a call without leaving the dashboard. Search also matches message text, and entries from Telegram no longer show a dead Discord link. Groundwork is in place for optional token info (name, price, market cap, liquidity) served by Trenchcord Cloud later
- **Bring-to-front hotkey** — set an OS-wide shortcut (e.g. `Ctrl/Cmd+Shift+T`) under Settings > General that raises and focuses Trenchcord from anywhere — click into Discord to reply, hit the key, and you're back on your feed (desktop app)
- **Threads & forum posts** — messages posted in threads and forum posts under a channel you monitor now reach your rooms (they previously never arrived, because Discord delivers them under the thread's own id). They're labeled `parent › thread-title` so you can tell which post a call came from
- **New Discord message formats render fully** — Discord's new "Components v2" bot messages (layout containers, sections, media galleries, buttons — used by newer tracking/caller bots) and **forwarded messages** used to show up completely blank. Both now render properly: text with clickable contract pills, images with lightbox, link buttons that work (interactive-only controls show disabled, as they only function in Discord itself). Crucially, contract detection, keyword alerts, notifications, search, trade buttons, **and the snipe engine** all see their text too — a CA hidden in a v2 panel or a forwarded call is caught like any other
- **Native Discord polls** — polls now render with their options and vote share instead of an empty message, update their percentages live as votes come in, can trigger keyword alerts, and show as `📊 question` in notification previews
- **Discord stickers** — sticker messages now display the sticker (including animated GIF stickers) instead of rendering blank
- **Tenor & Giphy GIFs, video embeds** — GIF links now autoplay as looping clips exactly like in Discord, directly playable videos get an inline player, and YouTube-style embeds show their thumbnail with a play button linking out. Previously these showed a static thumbnail at best
- **Full network transparency** — the README now has a "What Leaves Your PC" section documenting, in plain language, every single request the app makes off your machine: what triggers it, exactly what is sent, and what comes back. Any new outbound endpoint added in the future will be documented there as part of the change
- **Hiding a user also hides bot scans of their calls** — when you hide a user in a channel, replies that bots (e.g. Rick) post to that user's messages — typically the token scan their call triggered — are now hidden along with them, instead of leaving orphaned scans in the feed
- **Pushover notification per snipe config** — each snipe config can now push the result of every snipe it fires (bought or failed, with the token, SOL amount, and per-wallet outcome) to your phone via Pushover, with a chart link attached. The toggle lives in the config itself; it uses your global Pushover credentials and sound, and the config warns you right there if Pushover is disabled or its Application API Token / User Key are missing (desktop app)
- **fomo.family trade links** — Fomo joins Axiom, Padre, Bloom, and GMGN as a platform preset under Settings → Contracts, for both SOL and EVM contract links (Solana, Ethereum, BNB, Base, Robinhood, and more), and as an "Open Chart on Buy" site
- **"?" help next to the Pushover Application API Token field** — a small help icon now explains what the token is and walks through creating the Pushover application to get it, without opening the full setup guide
- **Settings search** — Settings has grown a lot of switches, so it now has a search bar: at the top of the settings sidebar on desktop, and above the section list on the phone. Type part of a setting's name (or a related word — "sound", "slippage", "proxy", "@everyone"…) and matching settings appear instantly with their section name. On/off settings show their switch right in the result row, so you can flip one without leaving the search; clicking any result jumps to its section, scrolls to the setting, and briefly highlights it so you land exactly where you need to be (all platforms)
- **All DMs — every incoming Discord DM in one room** — a new **All DMs** entry at the top of the sidebar's Direct Messages section collects every Discord DM as it arrives into a single feed, so you don't have to hop between conversations to see what came in. Each message keeps its conversation badge (click it to open the DM in Discord), and the room works everywhere rooms do: open it in a pane, pop it out, or give it a key under Settings → Feed Hotkeys. With **multiple Discord accounts** connected, each DM also shows a small **→ account name** badge saying which of your accounts received it — with a single account the badge stays out of the way. Like individual DM rooms, the feed fills live from the moment Trenchcord is running (all platforms)
- **Mute-all button in the chat header** — a speaker icon next to the pop-out button silences every notification sound Trenchcord plays (highlights, contract/keyword alerts, premium alerts, per-channel sounds) in one click; click again to unmute. The icon turns red while muted, the choice survives restarts, and sound previews in Settings stay audible so you can still test them. On the phone it lives in the header's ⋮ menu (all platforms)
- **Scripted promo scenes in the demo build** — alongside the full `?tour` walk-through, the demo now ships four fast-paced, hotkey-triggered marketing scenes cut like an action trailer (punch-zooms into the real UI, screen shake, flash frames, smash cuts, letterboxed slam typography, and synthesized boom/whoosh impact audio): `?scene` (the hero — "6 Discord servers. 3 Telegram cabals. One screen.", ending on a stylized pump chart with your buy marked early), `?scene=call` (a tracked caller drops a CA → one-click buy), `?scene=storm` (a multi-server message storm tamed with Focus mode), `?scene=confluence` (the same CA hits Telegram + two Discord servers, stacking up in the Contracts feed) and `?scene=ios` (the iPhone app — poses as the iOS shell so the mobile room bar and single-pane layout render in a browser, with a finger-tap cursor and tap-to-start; the whole app plays inside a drawn iPhone-15-Pro body — titanium rail, Dynamic Island, status bar, home indicator — on a showcase backdrop, with the camera zooms pushing in on the device; record it in a 9:16 viewport, or add `&noframe` for the raw full-bleed app in a phone-sized viewport). Each scene arms on a title card, starts on Space (which also unlocks the audio for the recording), and ends on a Trenchcord outro card; Space again reloads for an identical fresh take. Demo build only — nothing changes in the real app (demo)
- **Pull to refresh (iPhone)** — pull down on a chat room and release: a spinner appears, the app nudges its Discord/Telegram connections awake, and any messages missed while the phone slept are fetched in — the native way to un-stick a feed that looks frozen after the app was in the background. Two ways to pull: past the top of the message list (like Mail), or drag the room's header bar down — that one always works, even mid-scroll in a room full of messages (iOS)
- **Custom renames** — click a username in chat and pick **Rename User** to call them whatever you want. The custom name replaces their platform name everywhere in Trenchcord — messages, replies, the mute/highlight menus — for Discord and Telegram authors alike, and nothing changes on Discord itself. Renaming someone back to their real name (or a blank) clears it, and every rename can be reviewed and removed under Settings → Highlighted Users → **Custom Renames**
- **Server icon badges** — the source badge next to each message can now show the server's icon with just the **#channel** name (like Discord's own channel pills) instead of the full "Server / #channel" text. Servers without an icon get their initials in a circle, and hovering the badge still reveals the server name. On by default everywhere — each platform keeps its own switch under Settings → General → **Source Badge**
- **Mute by role** — right-click (or tap) a user and pick **Mute by Role** to see every role they hold on that server and mute one in a click: messages from *anyone* holding that role disappear from your feeds, server-wide. You can also browse a server's full role list in the room settings' new **Roles** tab and mute from there — no need to wait for someone with the role to post. Muted roles appear alongside hidden users in the chat header's "hidden" panel and in the Roles tab, where one click unmutes them. Role muting follows the member list live — someone who loses the role shows up again automatically. (Older messages loaded from history carry no role data, so a muted member's history only disappears once they've posted at least once while you watch)
- **Highlight by role** — highlight entire server roles the way you highlight users: pick them in the room settings' new **Roles** tab (each role can have its own highlight color), or right-click a user → **Highlight by Role** to toggle one of their roles. Messages from anyone holding the role light up with the room's highlight style and fire the same alerts as highlighted users — including Pushover. A role highlight marks the message row only — the author's name keeps its normal Discord role color, and the name only changes color when you highlight that user directly. A highlighted user always keeps their own highlight — their custom color, or the default blue — even when one of their roles is highlighted too: the role color only applies to members you haven't highlighted yourself. Both role features are documented in Settings → Help & Features under **Role Highlighting & Muting**
- **Setup videos on the landing page** — the Setup Guide's Discord Token and Telegram tabs now each open with a narrated ~45-second video walkthrough of getting your Discord token and your Telegram API keys, right above the written steps (web-optimized to under 2 MB each, showing the video's own title card until you press play). The old static screenshot of the token setup screen under the Discord steps is gone — the video covers it (landing page)
- **Unread badges now sync with Discord — both ways** — unread counters used to be Trenchcord-only. Reading a channel or DM in the official Discord app (phone or desktop) now clears the matching badges in Trenchcord: the app picks up the read receipts Discord already sends over the existing connection. And with the new **DM Read Sync** toggle under Settings → General (off by default), viewing a DM in Trenchcord marks that conversation read on Discord itself, so the badge disappears from your other Discord clients too. The other direction is DMs only by design — opening a Trenchcord room never marks its guild channels read in Discord. The aggregate All DMs badge only drops by the read conversation's share (other DMs may still be unread), acks hold while the Trenchcord window is unfocused so an open DM pane doesn't eat messages while you're away, and marking a channel as *unread* in Discord leaves Trenchcord's badges alone (all platforms)
- **All DMs: exclude users** — a new **All DMs** section in Settings (also reachable via the gear that appears on the All DMs row in the sidebar) keeps chosen users out of the aggregate All DMs feed, by Discord user ID or username (leading @ and letter case don't matter). Their DMs stop appearing in the feed and stop counting toward its unread badge, including DMs already in the feed's history — the individual DM conversations in the sidebar are untouched (all platforms)
- **Mentions from bots can now be filtered out** — a new toggle under Settings → Mentions controls whether messages from bot accounts (Rick and friends replying to or pinging you) land in the Mentions feed. It's on by default, so nothing changes unless you switch it off (all platforms)
